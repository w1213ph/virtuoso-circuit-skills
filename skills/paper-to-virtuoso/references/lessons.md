# 常见失误：出现什么，先查什么

本页把电路工程实践中的反复问题改成下一次 agent 可执行的检查。结论有适用范围，不是对所有 PDK、电路或仿真器版本的固定答案。按症状阅读相关行，详解见链接。

## 器件、模型与原生工程

| 容易犯的错误 | 为什么会误判 | 应怎样处理 |
|---|---|---|
| 同名 PDK 就用同一模型路径 | 工程可绑定不同版本、无源选项和尺度 | 回读实际库路径、技术关联、模型/section、保存状态和最终 deck；不全局覆盖用户 corner |
| 抄论文 W/L 或按工艺线宽等比例缩放 | 余量、阈值、寄生、噪声和负载不同 | 先做 gm/余量/带宽预算，再用目标 PDK 原生小样验证 |
| 只写可见参数、跳过回调 | 派生几何没变；初始化还可能重置 m/金属层 | 查实际 CDF，回传完整独立输入组，执行必要回调，读新进程 SI |
| 把所有参数转成字符串 | 整数段数可能静默回落默认，Check 仍零错误 | 保留 CDF 类型并检查实际展开段数和模型参数 |
| fw、nf、m 或实例数组重复乘算 | 显示值和模型 w 可能已包含指数量 | 分别记录单指/总宽/倍率/成员映射，以原生定义为准 |
| 觉得 R/C 值相同就器件等价 | RF 模型、金属层、段数与寄生改变动态 | 按用途检查模型和实际展开；不修改原厂模型来消除差异 |
| 合并层次时只按子电路名去重 | 同名 master 可能有不同端序/参数 | 按来源声明读端名，比较完整叶定义，按实际有效端序重接父级 |
| 表单保存/回调返回就宣布运行成功 | 网表失败也可能完成回调 | 核对最终 history、实际 deck、日志、数据和测量逐项对应 |
| Maestro 只复制主状态 | 测试子状态或当前交互配置丢失 | 连同 test_states 等本机实际依赖迁移，原生回读测试/变量/分析/输出 |

对应方法：[electrical.md](electrical.md)、[migration.md](migration.md)。

## 电气与测量

| 容易犯的错误 | 为什么会误判 | 应怎样处理 |
|---|---|---|
| 论文简图没画就省略辅助电路 | 正文/引用里可能另述共模、dummy、参考或时序 | 阅读相关正文和引用，列补充设计及未实现范围 |
| 差模 AC 通过就接长整机 | CMFB 或耦合环可能不稳 | 检查共模和各环、闭环扰动；冲突时核对断环条件与极点 |
| 满足饱和区就认为性能改善 | 更大 gm/不同偏置还会移动极点和信号范围 | 工作点、稳定性、噪声和动态恢复一起核对 |
| 小信号好就认为满幅也好 | 大摆幅可暴露跟踪非线性、压摆和共模恢复 | 同条件检查小信号与目标大信号；不把不同模块历史 THD 搬来作证 |
| 降噪/缩电容后只测一个指标 | 线性度、匹配、驱动和稳定性可能变差 | 用固定多指标合同比较候选，保留所有退化 |
| 模块单独通过就认为接起来通过 | 阻抗、共模和动态负载改变机制 | 加实际源/负载/参考/时钟；先接口测试再整机 |
| 理想缓冲隔离的 50Ω 当直接驱动 | 输出实际未承受该负载 | 测真实带载及输出阻抗，说明差分/单端/共模和参考面 |
| 比较器只看正负判决或 VALID | 参考反冲、记忆、迟到状态、旧码仍可能存在 | 扫真实阈值和输入历史，核对实际采样/判决时刻与每个码字 |
| 刺激参数名字看起来对就运行长测试 | 相位/直流参数在不同分析中用途不同 | 先画实际差模/共模激励及边沿，短测核对有效输入 |
| 单点外推高 IIP3 就当通过 | 残差、非三阶区或未收敛可产生虚高 | 分开 LO-only/双音，核对每音功率、两侧 IM3、斜率及谐波敏感性 |
| 把 0 dBm 设成关闭 RF | 0 dBm 是有限功率 | 根据实际源类型明确关闭激励，用最终 deck 核实 |
| SNDR 只挑最好窗口/初相 | 启动/共模仍可能恢复，窗泄漏也影响结果 | 预先固定窗口/舍弃条件，覆盖恢复、必要初相和全部带内失真 |
| 多段瞬态直接拼 FFT | 状态/相位不连续可制造成绩 | 核对重叠区实际波形/码字，否则用连续记录 |
| 理想重建或模拟节点成绩当数字整机 | 未验证实际码流、时序、校准和噪声 | 原生数字、模拟观察和行为诊断分别记录 |
| 零错误或短启动通过就称性能达标 | 不代表结果完整、稳态或目标已满足 | 分清运行完成、有效数据、指标通过、范围和剩余不确定性 |

对应方法：[engineering-circuits.md](engineering-circuits.md)、[bias-design.md](bias-design.md)、[simulation.md](simulation.md)、[optimization.md](optimization.md)。

## 绘图、协作与交付

| 容易犯的错误 | 应怎样处理 |
|---|---|
| 所有模块都是宽大空框 | 用最小可辨识功能图，按内容定尺寸；父级同步收紧并留出真实引线通道 |
| 全图全标签或为了紧凑取消实体反馈 | 保留主通路、合流和反馈；辅助跨组线才按需用同名短线 |
| 只看原点不看器件/参数包围盒 | 导出全图、关键局部和实际父级，分别检查文字/线/器件；纯排版核对网表不变 |
| 修改 symbol pin 只检查 symbol 本身 | 按实际 transform 核对所有受影响直接父级的端子和完整引出路径 |
| 重跑旧生成器覆盖手工修改 | 先回读用户当前坐标/朝向/线/标签/属性，再在独立库做增量修改 |
| 用全局 UI 缩放解决图面标注 | 字体/缩放可能造成表单重叠和画布裁切；优先局部图面整理，设置变更另做真实 GUI 检查 |
| 删锁/强制重载解决旧库引用 | 保留用户会话和在跑任务，隔离验证，安装/注销前核对实际占用 |
| 持续派发长仿真却不收取状态 | 记录自有作业、预算/超时/收取状态；用户停止后不追加；不碰其他进程 |
| 图纸写“去掉电容版”等过程名称 | 图面用当前功能和参数，历史变化进变更记录 |
| 交付一堆 JSON/日志或夸大完成范围 | 提供实际打开入口、简明说明与截图；参数、网表、行为、GUI 分开说明 |

对应方法：[drawing.md](drawing.md)、[symbols.md](symbols.md)、[engineering-schematic.md](engineering-schematic.md)、[acceptance.md](acceptance.md)。新问题按“现象→证据→原因或推断→修正→回归条件”记录，不把一次解决办法变成所有设计的硬规定。
