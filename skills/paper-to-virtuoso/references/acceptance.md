# 交付证据与验收

## 使用者先看这五项

1. **能打开**：交付中写明工程目录、库、顶层 cell/view 和仿真环境入口。
2. **能看懂**：全图看清信号流，局部看清功能、引脚和参数，symbol 与真实父级一起检查。
3. **能核对**：实际器件参数、逐端连接和原生网表有证据；纯重排需给前后比较。
4. **能判断结果**：说明哪些仿真实际运行、条件和指标是什么，哪些仍未验证。
5. **能继续维护**：给出文件清单、依赖、未完成项、备份和回退方法。

AI 应先给可读的工程说明，再附结构化记录。下面的细项供执行者逐项核查；不必让使用者从日志里猜工程入口或结果。

## 各类检查分别说明

以下结论各自独立；没有条件完成的项应明确写未验证。

| 类别 | 需要的证据 |
|---|---|
| 保存/提取 | Check & Save 的实际错误/警告数，逐条说明新增项 |
| 参数/连接 | 全部实例 master、完整属性/CDF、每个端子网络、端口方向和所属 net |
| Symbol | pin 集合/坐标/方向、有效端序、原生 NLP、独立选择框；直接父级已同步 |
| 网表 | 最终 OA 的原生 SI；重排前后比较保留 subckt 范围、端序、模型与参数 |
| 配置 | 原生读回每项 Maestro 测试绑定、模型、变量、分析、输出与保存状态 |
| 行为 | 用户要求的真实分析、history、deck、日志、数据、测量与条件 |
| GUI | 全图、关键局部、symbol 和实际父级截图，并实际目视检查 |
| 安装 | 新进程路径、文件哈希、连接/网表一致、受影响入口诊断对比 |
| 回退 | 可执行入口，隔离演练，遇锁/后来改动拒绝覆盖，保留无关配置 |

不能用截图证明连接正确，不能用 Check 通过证明画面好，也不能用载入模型/保存环境证明仿真达标。

## 电气回读 JSON

`audit_electrical.py` 接受单个 cell 或 `{ "cells": [...] }`。单个 cell 的必要字段：

```json
{
  "cell": "AFE_OTA",
  "ports": [{"name": "IP", "direction": "input", "net": "IP"}],
  "instances": [{
    "name": "MN1", "lib": "YOUR_PDK", "cell": "YOUR_NMOS",
    "props": [["l", "string", "180n"], ["m", "string", "1"]],
    "terms": [{"name": "D", "net": "OP"}, {"name": "G", "net": "IP"}]
  }]
}
```

记录全部端子和属性，上面仅为格式缩写。几何字段可以附加，比较器不把坐标变化当电气变化。Schematic 的 basic pin 图形实例可排除，顶层 `ports` 仍必须包含实际网络；缺少 net 字段不能静默通过。

`props` 的实例属性并不总涵盖全部有效 CDF 默认值，所以还须原生 CDF/网表复验。比较脚本证明“提供给它的数据一致”，不证明数据已经完整回读。

网表比较只归一明确的 cell 改名与按完整定义识别的 PCell 分配号，不删掉器件值、工艺角、精度、参数声明、分析或端序。额外模型和 VA include 可能在 SI footer，不能漏掉。

## 可读性检查

先看 fit-to-window 是否能辨别信号流和模块，再看关键局部是否有文字/器件/导线遮挡。确认差分镜像、真实连接点、非连接跨线和总线位序。symbol 缩小后，父级实例间距和线长也要同步收紧。

逐项填写模板的 `gui_visual_review.checks`，附实际截图和库/cell/view。对下列问题完成返工后再审图。

| 检查项 | 完成条件 |
|---|---|
| 主信号和朝向 | 输入优先左、输出右；父级旋转/镜像后仍可追踪，差分对应清楚 |
| 边框和功能 pin | 可见边界明确；图形通路连到对应 pin；偏置输出来源与传输门 A/B/控制能辨认；数字门形、反相泡、时钟标记符合真实逻辑 |
| 导线间隔和交叉 | 出 pin 后向外引出，转弯位于独立通道；无贴边、绕框、异网交叉和模糊线端 |
| 尺寸和标注 | 常用缩放能辨认功能，局部能读清 pin/参数；没有无用途的大块空白、挤字、叠字或穿字走线 |
| 工程注释和接口说明 | VCO 结构/级数/控制与性能条件、偏置供给对象/工作范围、TB 参数绑定/测试指标按实际对象填写；非电源 pin 表与当前端口一致 |
| 逻辑与配置映射 | 适用时有真值表、状态摘要或表达式；配置码与增益等功能量对应清楚，位序、默认码、目标/推算/实测及条件分开 |
| 实际直接父级 | 所有受影响直接父级与 TB 均有核对记录；尺寸、引出路径和变换后 pin 已同步 |
| 供电线层级 | 标明实际支持与验证范围；独立加粗需有原生保存回读、网表及 GUI 证据 |

`reviewed_views` 记录实际看过的视图、缩放/局部范围与证据路径。`open_issues` 保留尚未修复的问题。只有截图文件、没有实际查看时保持 `not_verified`。检查失败写 `failed`；确实不适用的项目写 `not_applicable` 并附原因。旧任务缺少新增字段时补做相关检查，已有记录可保留。

供电独立线宽不支持或未验证时，明确记录限制，其余图面项目可以分别完成。本模板的状态由执行者据证填写，离线仓库检查只核对文件与工具行为。

提交 `assets/acceptance-template.json` 的实际填写结果，附证据路径。不要预填 PASS；检查项无实际文件时不能宣称完成。

工程化注释另核对：每组作用明确，目标与实测分开，数值带条件；短引出线使用实际 wire label；标题栏按内容定大小。可按[晶体管级规范](engineering-schematic.md)和独立 OTA 示例检查。

更新参数或端口后核对旧注释是否失效。VCO 级数/抽头、偏置去向、测试条件和码值映射都需回读依据，结果注释链接到同一电路版本的实际测量。完整非电源接口释义放在右下角或其他留白区，避免撑大 symbol 或压住连线。

## 片内实现规模

填写 `physical_implementation`，按 [physical-sizing.md](physical-sizing.md) 附 MOS 与 C/R/L 的有效参数、层次展开总量、面积依据及已知预算。`large_device_exceptions` 记录确需大器件的名称/总量、必要性、代价、替代比较和向使用者的说明。空列表在状态未验证时不代表没有大器件。

面积估算、实际 PCell/版图尺寸和签核完成范围分别说明。纯改图/迁移/导出时按范围标记，发现现有大器件可记录为观察项。

## 新电路的工程完整性

按[复现流程](paper-reproduction.md)给出当前阶段和实际证据，检查论文原有、补充设计、理想替代和未实现部分。依据[工程模块检查](engineering-circuits.md)选择适用项目：

- 偏置/参考的来源、分配、负载和启动依赖明确；适用时检查启动、关断、修调、余量与恢复。
- 差模与共模、局部环与整机、隔离参考与真实动态负载分别验收。
- 开关/比较/数字链的实际相位、极性、总线/数组展开和样本对应明确。
- 保留真实源/输出负载；理想参考、时钟、观察缓冲和行为块的影响与功耗包含范围明确。
- 图面能解释当前功能、设计理由与条件；没有迭代过程名称或过期数值。参数来自实际数据库，实测注释有对应版本的证据。

端口比较需展开总线成员并保留位序/方向；仅比较 terminal 数量可能把一个总线端口与多个标量端口误判为不一致。端名/方向一致仍不代替实际网络与有效网表端序检查。
