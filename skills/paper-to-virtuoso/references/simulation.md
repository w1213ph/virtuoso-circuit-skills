# 行为验证的适用范围

纯重排/改 symbol/迁移环境：比较电气、回读设置和目视画面，不自动跑长仿真。新论文或明确性能优化：先模块再整机，并对最终 OA 原生网表复验。探索 deck 不代替交付电路。

## 前仿计划与指标记录

用 `prelayout.json` 为当前任务写一组需要判定的测试。每项有稳定 ID、指标、单位、原生测试台、分析类型、工况、测量定义和目标来源。按电路和用途选分析。为 PVT 和失配写出实际选用的 corner、电压、温度、随机模型、样本数与判据。可逐工况建测试，也可记录约定的最差值或统计量并保留分项证据。

余量很小时，先固定原网表、偏置、负载、时序和指标，再抽局部失配样本。用同尺寸的一对器件检查零扰动、相反扰动、交换扰动及并联有效面积对电流差的影响。零扰动的完整电路应复现标称结果，重复种子应复现原波形的测值。各项合格数量和同一样本全部达标数量分别报告，记录失调的符号、工作点和独立终点。[慢角采样余量、失败种子与独立复算](../../../examples/sky130-adc-driver/README.md#slow-corner-mismatch)

以下比较器计划用于展示格式。示例的激励、负载和限值由实际任务替换。

```json
{
  "schema_version": 1,
  "inputs": ["netlists/comp.scs"],
  "reference_inputs": ["simulation/bench-models.json"],
  "tests": [{
    "id": "COMP_DELAY_TT",
    "metric": "决策时间",
    "unit": "ns",
    "testbench": "TB_COMP_DECISION",
    "analysis": "tran",
    "conditions": {
      "corner": "TT",
      "temperature_C": 27,
      "supply_V": 1.8,
      "clock_rise_ps": 50,
      "input_common_mode_V": 0.9,
      "input_delta_mV": 5,
      "output_load_per_pin_fF": 30
    },
    "measurement": "从评估时钟 50% 到正确极性的差分输出达到 0.6 V，且在该周期保持判决",
    "target": {
      "source": "待确认的示例目标",
      "confirmed": false,
      "limits": {"<=": 8}
    }
  }],
  "results": {}
}
```

- `inputs` 绑定该候选的原生 DUT 网表、实际 deck 等会随电路变化的输入。`reference_inputs` 放基线和候选共用的测试台、模型/角选项清单、激励、负载、测量程序或其文件清单。测试条目可追加自己的 `inputs` 或 `reference_inputs`。路径相对于计划文件。模型和 include 依赖如由清单表示，应在运行前从实际依赖重新生成清单并记录文件摘要。
- `target.limits` 支持 `>`、`>=`、`<`、`<=` 和 `==`。可合并多个判据。指标未定时用 `target: null` 或 `confirmed: false`，先记录测量或补齐验收条件。
- 仿真前用 `snapshot` 取得每项 `context_sha256`。仿真后，`results` 以测试 ID 为键，记录同一次运行的 `context_sha256`、`status: "measured"`、有限数值 `value`、同计划单位 `unit` 和 `evidence`。`evidence` 是文件路径到 SHA256 的映射，可包括求解日志、原始数据、测量输出和相应的测试条件。保留求解失败时可写 `status: "run_failed"`、`reason`、当前摘要和证据。
- 用 `check` 核对记录内的阈值、单位、输入和证据。整理或更换条件后从实际运行重新采集，旧尝试留在原任务记录。用 `compare` 对照相同测试定义及共用输入的基线和候选，核对变化量与候选是否满足全部约定限值。命令见[工具用法](../../../docs/TOOLS.md#核对和比较前仿记录)。

上述工具基于声明的文件和记录的数值。原生验收时仍需核对实际 Maestro history、网表、求解日志、波形和测量脚本，确认测试台在正确的工作点、模式和加载条件下运行。

## 模式、负载与测试用途

可编程信号链先从实际父级网表对应上下级的差分端子、总线位序和负载。把控制码追到选通支路，也查常通支路、关断支路和测试开关。相邻码可能选中同一支路，另一组位也可能单独改变偏置。给出码到 dB 的关系时，写清测量频率、输入幅度、负载、共模和使能状态。图上的译码表能解释开关选择，带负载的增益还要从电压或功率测量得到。

每项前仿按它要回答的问题选择观测点。用 `conditions` 记录本次控制码、实际测量的父级节点、所接下一级，以及偏置或负载采用的视图。把相关 config、生成的网表或测试台清单放入 `inputs` 或 `reference_inputs`，使复跑能发现条件变化。若外部理想源本来就在用户约定的接口上，可以用它验收该接口。若用理想源替代待验证的片内模块，其结果适合定位问题。

正式指标沿用默认的 `role` 值 `acceptance`。定位问题的测量可单独设置 `"role": "diagnostic"`，例如测采样开关两端的压差。脚本同样检查原始证据和输入摘要，核实后显示 `DIAGNOSTIC_MEASURED`。诊断值可以与自己的参考阈值比较。整机是否满足规格由正式指标决定，只有诊断项的计划仍需补充验收。[开源案例中的同一条采样波形](../../../examples/sky130-adc-driver/README.md#跟踪误差来自哪里)

在多档设计中，把需要核对的组合写进 `required_sweeps`。例如增益应覆盖四个控制码、三个工况和指定的接收节点。留意最低码的固定支路、互补栅极的实际直流电平，以及测试引出与正常信号路径的负载差异。切码测试可用独立静态工作点给出起点与终点，从实测控制边沿计时，输出进入误差带后要保持到约定的观察窗口结束。写明实际测试了哪些转换和位间偏斜。[覆盖字段示例](../../../docs/TOOLS.md#检查控制码和工况是否跑全) · [带接收级的四档增益案例](../../../examples/sky130-programmable-gain/README.md)

## 模拟与共模

放大器驱动 ADC 时，从量化跨度和位数确定允许误差，用实际输入步幅和跟踪窗口估算带宽，从工艺表选择尺寸。在测试台保存目标输入、放大器输出、采样电容电压和实际互补时钟。分别测上升和下降、关断前和保持期间；电容与驱动输出之间的差值可以定位开关充电不足，驱动输出相对目标的误差可以暴露有限增益或驱动能力。分别检查开关导通和断开时的闭环工作点、带宽与相位裕度，随后用时变电路验证双向大信号建立。全差分驱动还需验证共模反馈。[可复跑的单端采样驱动实例](../../../examples/sky130-adc-driver/README.md)

记录负载、偏置、模型、corner、温度和精度。差模增益/PM 不等于 CMFB 稳定；多个共模环路需选择合适探针、检查真实 STB 警告，并用足够长的扰动恢复交叉。短时域看起来改善不能推翻明确的不稳定结果。

比较器单独极性通过不代表整个 Flash 通过：加入真实参考梯、时钟和 kickback 后检查阈值、动态参考压降和码字。SAR 检查实际比较器判决、CDAC 共模范围、VALID、码字保持和采样相位。

## 周期 RF

条件适用时优先 HB/HBAC/HBSP/HBNOISE，按用户要求选择；保留必要的启动/瞬态交叉。PSS 慢或不收敛不意味着 HB 自动正确。

小信号 LO-only 与双音 IIP3 分开。确认命名基波、谐波截断、LO 波形和端口归一。每音 PRF 单独定义，0dBm 不是“关断”。IIP3 至少核对两侧 IM3、输入功率扫描和三阶斜率；单点外推只报初筛。高阻电压换算的 OIP3 不是真实 50Ω 驱动能力。

## ADC / CT 系统

先稳定参考、偏置和模拟环路，再检查启动、真实时钟边沿、码字延迟、互补及数字重建。原生瞬态 + 正确采样/FFT 适合 ADC 的序列指标，不能机械照搬 RF 增益/NF 定义。

保存 Fs、FIN、NFFT、窗、舍弃长度、信号 bins 和全部带内噪声/失真计数。含噪声结果保存 noisefmax/noisefmin、seed、实际有效低限及时间记录。频带和多个随机记录未收敛时不能称稳健达标。

行为模型、理想数字、原生器件和实测结果分开。人为噪声预算与理想 FIR 系数不能用来宣称工艺噪声/SNDR。校准算法可先参考实现，但要标明是否真正跑过原生校准、逐单元失配和半速模式。

## 原生环境完成判据

若用户要求实际运行 Maestro，检查已接受的 history、每项最终 deck、求解日志、PSF 数据和测量。完成回调只说明流程结束，网表失败也可能触发回调。对失败 history 原样保留。
