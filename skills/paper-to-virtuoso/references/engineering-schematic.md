# 让晶体管级原理图容易读、容易交接

这是晶体管级 schematic 的补充规范。Symbol 继续采用已有的[功能 symbol 规则](symbols.md)和 CTDSM18 图形基准，不因为学习工程 IP 就换一种画法。

## 先读懂电路，再排图

先建立“器件—作用—所属功能组—关键网络”的清单，再画器件。按实际机制选择偏置、输入跨导、负载、再生、输出缓冲、CMFB、复位等分组，分组数量由电路决定。一组内部能顺着主通路读完，跨组接口有明确名称。复杂运放的主放大链与辅助共模环分别排布；比较器把前置放大、再生和保持/复位关系说清楚。

相同作用的晶体管放在相同高度；对应支路围绕中轴等距。电源向上，尾电流和地向下。镜像时按真实 master 重算全部端子，包括体端；尺寸相同并不能证明连接对称。布局要求中的匹配组可写在相应功能组旁，不能据此宣称已经完成匹配版图。

## 实体线与同名网标怎么取舍

先画出组内主信号、电流合流、局部反馈、补偿、二极管连接和再生交叉耦合。公共电源、体端、远距离偏置与跨组控制优先使用短引出线和同名网标。

当一条跨组线造成多次绕行，或穿过另一组器件及参数区时，可将它改为两端同名的原生 wire label。电流镜的跨支路栅极连接也可按用户偏好采用同名网标，但参考支路的二极管连接和输出支路仍应直观可见。不要逐个晶体管的每个端子全部标签化，让读者重新拼拓扑。

体端优先从实际 B 引脚水平短引出，网标放在外端，留开 CDF 参数的范围；不要为了摆放网标再折一小段。差分两侧保持短线长度和标注方式对称。

这里的“飞线”是**与端子真正连接的短 wire + 原生 wire label**。普通文字、装饰线和仅用于提示未连接的 flight line 都不能代替它。同名关系在当前层次中核对；跨层用实际端口连接，不随意加全局 `!`。一条网使用一个规范名，不把同一根线同时命名成接口名和内部别名。

## 工程注释写什么

每个功能组写清“名称、作用、关键条件或大致指标”。需要数值时明确区分：

| 状态 | 合适的写法 |
|---|---|
| 设计目标 | `Tail target: 40 uA`，尚未实测 |
| 仿真结果 | `Tail measured: 35.82 uA / TT, 1.2 V, 25 C`，附结果记录 |
| 推算值 | `gm/CL estimate`，注明公式和近似条件 |
| 尚未验证 | 直接标为未验证，不用典型值填空 |

峰值电流、平均电流和静态电流分开；单位、积分窗口、负载和工作模式影响结论。失调、延迟、增益、带宽、功耗只写本次实际测过的项目。参考 IP 上的旧注释是设计者留下的资料，不能转成新工艺的实测结论。

标题栏保留电路名、用途、版本；条件栏写工艺、电源、corner、温度和负载；必要时加验证记录索引。按内容定边框大小，避免固定大纸框让电路缩成一团。组标题、功能说明、器件参数采用有层级的字号；字体沿用 roman。原生 CDF 标注与手工功能文字分开，参数不手抄成会过期的第二份真值。

### 注释保留工程信息，图面只表达当前设计

注释按阅读层次组织：整图的用途和接口条件；功能组的作用与设计理由；关键支路的偏置/共模/补偿/时序与匹配关系；需要时附带条件的目标或实际结果。主图放理解电路所需的信息，完整测量数据可用证据索引链接。不要为了模仿参考图的简短注释，把“为什么这样连接”删掉。

可采用以下格式，填本次事实，没有测量就保留“待验证”：

```text
功能：差分增益级 / 共模控制 / 参考分配等当前作用
机制：控制哪个节点，维持什么关系；对应真实支路
条件：电源、模式、输入共模、实际负载和必要相位
目标：本次设计目标及预算依据
结果：实际测量值＋模型/corner/温度＋证据索引，或“待验证”
注意：匹配组、极性、启动/关断、输出余量或时序约束
```

图纸标题、cell 和 symbol 使用当前功能及必要结构特征，标注当前实际参数。不写“去掉电容版”“缩小版”“改进版”“最终版”，也不在主图写本轮优化故事。修改原因、前后差异和候选记录进入任务变更文件。已有版本元数据可保留在记录或独立管理字段，不能用过程名称替代功能名。

原生 symbol 编辑视图中的 `cdsTerm(...)`/NLP 表达式与实际父级中的显示不同。必须在真实父级审查大小、端口分组和文字；不能因为编辑视图表达式互相靠近，就把它们全部改成普通文本。参考中装饰图案、陈旧改动文字和拥挤局部不属于新图的目标。

### VCO、偏置与测试台的具体注释

先从当前层次、原生参数和实际测试配置回读信息，再填写相应内容。长表放在空白注释区，symbol 保留可辨识功能和简短摘要。

| 对象 | 图上应能读到的内容 | 数值与证据核对 |
|---|---|---|
| VCO | 环形/LC 等实际结构，单端/差分，电流饥饿/延迟控制等方式，实际级数，连续运行或复位机制，控制端与输出抽头 | 级数从闭环实际延迟单元计数，单独记录输出缓冲与抽头数量；给出控制偏置/范围、电源/负载及带条件的频率、调谐范围或 KVCO |
| 偏置 | 参考来源、产生/镜像/分配机制，每个输出供给哪个模块、支路或管栅，电压/电流类型，使能/启动/关断和设计特点 | 记录目标与已测电压/电流、可用输出范围、实际负载、余量和 corner 条件；说明该偏置如何设定对应模块的工作点 |
| 测试台 | DUT 和测试目的，模型/section/corner、电源、温度、输入/共模/时钟、真实负载，关键变量取值，分析及测量定义 | 标明参数单位及其实际绑定位置，区分源峰值/峰峰值/差分幅度/每音功率；时间窗、舍弃时间、频率范围和功耗包含范围与实际 worker/deck 一致 |

VCO 的级数、抽头数和边沿计数分开说明。KVCO 注明 Hz/V 或 rad/s/V，以及控制工作点/区间。只有短瞬态结果时，就写该偏置与负载下的短测频率或启动观察；相噪、PVT、全调谐范围等分别保留实际状态。

测试台让下一位使用者知道“改哪个变量、在哪里设置、会测到什么”。例如电源变量绑定哪个源，控制电压来自理想源还是实际偏置，输入采用什么波形，测量哪个节点/码字。变量名必须对应实际 Maestro 或 deck。

可采用以下待填写摘要，每行独立生成原生 label，替换全部占位后再加入图纸。

```text
VCO  [structure], [N] delay stages, [single-ended/differential]
Control  [pin], [bias/range + units], [continuous/reset mode]
Load  [actual load and readout], Output  [node/taps]
Target  [frequency/range + conditions]
Measured  [result + conditions + evidence], or Pending

BIAS  [reference and generation method]
[pin]  [voltage/current target], drives [actual block/branch]
Range  [output/load limits], Mode  [enable/startup/shutdown]
Measured  [value + conditions + evidence], or Pending

TB  [DUT], measures [specific performance]
Setup  [model/section/corner], [VDD], [temperature], [load]
Stimulus  [variable=value+units], [bound source/pin], [waveform]
Analysis  [type], [range/window/discard], [output/measurement]
Result  [measured/target/pending + evidence]
```

### 模块接口说明放在独立留白区

在模块 schematic 右下角或邻近留白处放紧凑接口表，避开主信号、反馈和器件参数区。复杂模块可分组排列，表格按内容收紧。常规 VDD/VSS/GND 等电源地省略释义；VCM、VREF、偏置、控制、时钟和数据端仍需解释。多电源域的电压/上电约束另放条件栏。

| Pin | 意义与供给/接收对象 | 必要的极性、电平、时序或位序 |
|---|---|---|
| 按当前端名填写 | 具体作用，连接到哪个模块/支路 | 数值标明目标或实测及条件 |

例如 VCTRL 写控制作用和有效范围，BN/BP 写给谁的哪类栅压，EN/ENB 写互补关系及导通/关断条件，PH 总线写抽头/相位顺序，数据输出写位宽、编码和有效时刻。端名、方向、总线成员与实际 terminal 和父级一致。

完整接口释义留在 schematic 注释区，symbol 的 pin 标签保持简明。在父级常用缩放检查摘要，在局部检查表格。端口改名或参数更新后同步表格及受影响父级。

### 数字逻辑的真值表与状态摘要

对输入组合不多、又需要解释模式选择或控制逻辑的模块，在接口说明旁列简短真值表，写清关键 0/1 组合对应的输出。普通 INV/AND/NAND 等已由标准门形清楚表达的简单功能可以省略。复杂译码、计数或状态机采用逻辑表达式、模式表或状态转换摘要，并链接详细说明。

| 输入/控制组合 | 输出或下一状态 | 条件与说明 |
|---|---|---|
| 由实际逻辑填写 | 由原生连接或逻辑推导 | 有效电平、使能、复位、保留状态 |

先确认高/低有效、复位优先级、时钟边沿和输出延迟。组合逻辑用真值关系，时序逻辑记录当前状态、事件与下一状态。表中的 X 若表示无关项应注明，不能与仿真未知态混用；Z、未定义或保留码按实际实现说明。推导表与已做的行为验证分别记录。

### 配置码与增益等模拟量的对应

可变增益、可编程 R/C、偏置修调及模式选择，必须说明输入码如何影响实际功能。写明总线范围和位序、编码方式、有效极性、默认/复位码，以及有效码和保留码的处理。增益区分电压/电流/功率及线性值/dB，按任务说明差分/单端参考面。

| 配置码 | 实际选择/比例关系 | 目标或推算增益 | 实测增益与条件 | 备注 |
|---|---|---|---|---|
| 由实际位序填写 | 开关、反馈比或选中支路 | 写清单位与依据 | 模型/电源/温度/频率/负载及证据，或待验证 | 默认、保留码或切换约束 |

码数少时完整列出，码数多时用经核对的公式/分段关系与关键码表，再链接完整 CSV 或测量记录。只测试了部分码时明确覆盖范围。配置表来自实际译码、器件比例和当前测量，不能用理想等步进填充未验证的实测列。

## 可直接使用的注释模板

在仓库根目录运行：

```sh
python skills/paper-to-virtuoso/scripts/emit_schematic_notes.py --library YOUR_TEST_LIBRARY --cell YOUR_TEST_CELL --annotations skills/paper-to-virtuoso/assets/engineering-notes-example.json --out build/engineering-notes.il
```

先复制并修改 JSON 中的文本、条件和坐标。文件中的实测数值属于[六管 OTA 演示](../../../examples/engineering-ota/README.md)，不适用于你的电路。生成器只生成 `.il` 文件；把它传到能运行 Virtuoso 的环境，再在**已备份的独立测试 schematic** 中审核并加载。工具仅追加原生文字和注释边框，不创建电路、不改连线、不改 symbol；现有同 owner 注释会拒绝重复添加，以保留后续手工编辑。

加载成功会打印 `VCS_NOTES_PASS` 和前后相同的 Check 计数。计数相同并不能证明位置合适；还需比较原生网表、检查全图/局部/父级。注释保存在 schematic 内，字体显示、文字宽度和合适坐标依赖目标环境。恢复备份视图可回退；不要用整库覆盖恢复去丢弃其他单元的后续工作。

## 验收到什么程度才交付

1. **连接与参数**：保存后回读实际器件、全部 typed 参数、逐端网络、端口方向；所有同名短线的归属正确。
2. **网表**：只改注释或排版时，前后原生 SI 电气定义一致。器件内部 PCell 编号变化按完整定义核对，不按名字猜。
3. **行为**：新建电路运行对应模块测试；只排版不强行重跑长仿真。实测注释有原始结果与条件可追溯。
4. **图面**：实际打开并查看全图、关键局部、symbol 在父级的常用大小；器件和参数清楚，文字不压线，正负端、时钟和偏置归属易认。静态截图通过不承诺任意缩放都能读到全部参数。

这次方法从可访问的工程参考中提炼，公开内容只包含通用做法和独立新建演示。参考 IP 的数据库、截图、厂商标题栏、尺寸及专有拓扑不在发布内容中。
