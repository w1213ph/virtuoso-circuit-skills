# 让 agent 有效率地优化结构与参数

用于用户明确要求性能优化的任务。仅画图/迁移时不进入此流程。优化的目标是用有依据的实验找到满足约束、可以原生交付的电路，不是生成最多候选或最高单次数字。

## 1. 固定比较合同，建立可复测基线

先记录当前已保存 OA 与用户修改，取得实际原生网表，核对实际 deck、模型版本/corner、激励、负载、精度与测量。把指标分成硬约束、主要目标和次要代价；明确是在标称条件优化，还是已授权包含哪些 PVT/失配条件。

| 类别 | 例子 | 比较原则 |
|---|---|---|
| 必须先满足 | 连接合法、启动/稳定、额定电压、功能/时序正确 | 不通过就不能靠其他好指标抵消 |
| 设计约束 | 功耗/面积上限、增益/噪声/线性度/带宽范围 | 按用户当前阈值筛可行解，不能临时改指标 |
| 可行解中的取舍 | 更低功耗、更小面积、更高余量 | 保留 Pareto 候选；让用户目标决定选择 |

没有稳定基线时先排错。把原电路与候选放在相同条件下比较；若基线与历史条件不同，先建立新基线，不把差值都归因于器件改动。

## 2. 先找限制在哪里

沿信号/误差传播建立分模块预算，读工作点、共模、摆幅、噪声分量、时序与源/负载。根据失败现象选择最便宜、能区分原因的测试：

| 现象 | 优先诊断 | 可能选择的方向，需验证 |
|---|---|---|
| 增益或带宽不足 | gm/ro、输入/输出加载、主极点和实际反馈 | 电流/尺寸/补偿联动；必要时更换级数或读出接口 |
| 噪声不足 | 实际带宽、哪个支路/接口主导、是否含噪声折叠 | 调整主导源及阻抗分配；不是全局增大电流或位数 |
| 大信号失真 | 各级残差/谐波、余量、动态跟踪、共模和参考反冲 | 局部反馈/退化、共模/驱动、开关相位；计入噪声/带宽代价 |
| 只有启动/特定初相失败 | 偏置依赖、辅助环恢复、迟到状态和复位 | 修启动/时序/环路，不用挑初值和 FFT 窗掩盖 |
| RF 匹配/增益互相牵制 | 实际时变输入阻抗、加载、无源损失和反向传递 | 先改接口/阻抗/结构；不能拼接隔离模块的好结果 |
| ADC 精度上不去 | 保持节点与真实码字的分别误差、参考、时序、重建 | 先定位模拟/采样/数字误差，不直接增加位数或理想校准 |

诊断可使用理想源/断环/替代负载来区分原因，但只能标为诊断证据。选定改法后回到原真实整机接口验证，不能把去掉困难负载后的成绩当设计通过。

## 3. 结构优化与参数优化分开

结构候选改变极性/反馈/级数/开关方案/读出方式等，需要重新确认机制、端口和稳定性。参数候选只在已明确结构中变化。每个结构单独保留基线、测量合同和参数空间；两个层次混在一次大扫描里，既昂贵又难归因。

为结构候选写：限制机制、预期改善、代价、最小证伪测试。接口或噪声预算已说明结构难以满足目标时，先做少量结构对照，不继续无边界调 W/L。参数还有明显有效方向时，也不急于换架构。

## 4. 降低参数维度，先筛敏感变量

用有物理意义的参数组：支路电流/镜像比、gm 与过驱动/余量、L、单位电容与倍率、RC 时间常数、反馈比、相位/延迟。匹配输入/反馈跨导或 I/Q 支路应按设计关系联动；不要把每只 MOS 的 W 都当独立变量，也不要默认同宽就应同改。

记录合法范围、离散值和约束关系。单位单元/nf/m/segments 必须按真实 CDF 定义；每次生成候选后重新回调、回读并核对原生网表。

在基线附近先做少量单方向或成对扰动，估计指标变化与数值噪声，找有效且可解释的变量组。正值连续参数通常适合比例步长；零值、有符号量、dB 值和开关拓扑不能盲用对数敏感度。效应低于测量/数值不确定性时，不据此继续细扫。

变量少时可用粗扫→缩小范围→局部联合搜索；明显存在相互作用时补小型组合试验。单次原生仿真昂贵且参数空间已经定义清楚时，可考虑有约束的代理模型/贝叶斯搜索；样本不足、离散拓扑突变或失败状态很多时，不把拟合器当电路原理。无需为了“智能”先引入复杂优化框架。

## 5. 用逐级测试减少无效长仿真

推荐按依赖筛选：合法 CDF/网表→DC/余量与功耗→短启动/稳定/功能→相关小信号或局部机制测试→整机名义性能→必要的精度敏感性/PVT/失配。

筛选条件依电路调整：有些电路必须先检查长共模恢复；RF 周期小样也不能替代自然启动。短时、少频点或较低计算成本的筛选只用于排序，不能提前宣称全部约束通过。最终候选要在固定的完整验收条件复验；不得放松模型、精度、负载或删掉不利频点来获得好结果。

## 6. 每次计算都留下能复用的记录

候选记录至少包含：ID、结构、基线、假设、变化参数、OA/SI/deck/模型/激励/测量标识、运行状态、错误/警告、各指标、成本和下一步。可从[候选表模板](../assets/optimization-candidates.csv)开始，指标列按任务扩展。

相同条件和相同输入可复用已完成结果；缓存键必须包含模型及其依赖、分析、求解设置、激励/负载和测量脚本版本。改电容/偏置/模型后，不能把旧完整成绩挂到新 OA。结果缺失、超时、收敛失败、未达标分别记录，不能都记作低分，也不能用部分数据补成成功。

只并行独立候选，限制总求解线程/内存，避免“并行任务数×每任务线程数”过量。管理任务自有进程组、超时和收取状态；断线后查真实状态再恢复，避免重复派发；不干扰用户会话或其他仿真。

## 7. 预算、停止和最终交付

开始前确定这轮的候选数量/计算时间/可用资源及需要覆盖的条件。按机制分批推进，每批后比较收益、代价和剩余不确定性；优先测会改变下一步决定的内容。

满足以下情况应结束当前搜索或改变路线：已达到全部本轮验收条件并有必要余量；小范围改动的改善已经低于数值/统计不确定性；连续多批出现同一机制限制；预算用完；用户要求停止。预算用完只能报告当前最好可行解和未解决项，不能写成目标已达成。结构路线变化涉及超出授权的功能/功耗/工艺目标时再向用户说明选择。

最终候选用其 OA 的新进程原生网表复测关键条件，核对实际 Maestro history/deck/数据；安装后再次回读。保留一张多指标表和未验证项，图面只描述最终功能和当前参数，候选名/优化过程留在记录中。
