# agent 电路工程搭建与论文复现流程

面向“用户给论文和目标，agent 完成工程”的任务。也适用于没有论文的新电路设计：把论文依据换成用户需求及明确的设计假设。仅改图、迁移和导出仍按原任务边界执行。

使用 [设计记录模板](../assets/paper-reproduction-template.md) 建立任务记录。记录可以分文件，但每项结论要能追到电路版本、模型/激励和实际证据。下表是阶段依赖，不要求所有电路做同一套分析。

按任务先查 [lessons.md](lessons.md) 的常见失误；性能优化按 [optimization.md](optimization.md) 执行。已有工程从当前 OA/模型/结果建立基线，不重做与本次无关的阶段；已有电路集成仍需补真实接口验证。

```mermaid
flowchart LR
    A[论文与需求] --> B[机制与工程分层]
    B --> C[PDK 映射与预算]
    C --> D[关键模块验证]
    D --> E[真实接口与整机]
    E --> F[指标测量]
    F --> G[图面复核与交付]
    D -. 失败定位 .-> C
    E -. 接口或稳定问题 .-> D
    F -. 机制假设与有限候选 .-> C
```

## 从输入到交付

| 阶段 | agent 的工作 | 产物 | 进入下一步的条件 |
|---|---|---|---|
| 1 明确目标与能力 | 读取本地规则、现有工程和连接；确定论文版本、图号、工艺、电源、指标优先级 | 需求与能力清单 | 设计范围、可执行环境、测量定义明确；只询问真正阻断的缺项 |
| 2 还原论文机制 | 阅读相关全文及图表；追清信号、反馈、电荷、时序和噪声路径 | 架构图、机制解释、逐项来源、缺失电路表 | 区分论文原有、补充设计、理想替代和未实现；不能用性能表代替电路解释 |
| 3 拆分工程模块 | 按核心、偏置/参考、共模、控制、时钟、输出和测试台分层；定义端口 | 层次清单、接口表、依赖图 | 方向、极性、总线位序、共模/负载、电源/体端明确；无未处理的启动循环依赖 |
| 4 查真实 PDK | 探测器件、CDF、回调、额定电压、几何、模型与尺度；少量原生回读 | 工艺映射表及合法器件小样 | 有真实 master 和端子；输入值类型、nf/m/段数和新进程原生网表一致 |
| 5 做电气预算 | 按机制估算 gm、余量、噪声、负载、时序、功耗；检查片内 MOS/C/R/L 规模与面积 | 带条件和近似的预算、大器件说明、待验证清单 | 有可解释初值和测量办法；工程模块与器件规模有依据，已知面积约束满足 |
| 6 验证关键模块 | 独立库搭建关键核及相应 TB；先排激励/模型/连接问题 | 原生 schematic/symbol、模块数据、失败记录 | 实际工作点、极性、稳定性或时序满足其接口；理想替代的边界明确 |
| 7 接入整机 | 用实际源/负载、参考、时钟和控制连接模块；逐步替换理想块 | 整机 OA、原生网表、整机 TB | 接口加载、反冲、共模、启动和控制模式通过相应检查，才能做长时性能测试 |
| 8 按定义测量 | 在约定条件下运行分析；对机制相关参数做有限比较 | 指标表、原始数据与条件、论文差异说明 | 结果完整且可复测；数值设置/记录长度的关键敏感性有检查；未达标明确保留 |
| 9 冻结并审图 | 保留用户修改，整理功能区、对称、symbol、注释和父级 | 全图、关键局部、实际父级及前后电气对照 | 参数/逐端/网表核对与图面检查分别完成；纯排版不改变性能设置 |
| 10 安装与交付 | 备份、精确安装、用新进程核对；写打开方式、依赖和回退 | 可打开工程、证据索引、可执行回退 | 交付路径真实可用；没有把历史结果套给新参数；没有遗留未说明的任务作业 |

图面质量从模块初建开始执行，第 9 阶段是完整复核。不要先堆出无法阅读的整机，再靠更大画布掩盖层次和接口问题。

器件规模按 [physical-sizing.md](physical-sizing.md) 记录。审图逐项检查可见边框、功能图与 pin 的对应、主信号朝向、贴边/交叉/标注问题及父级尺寸，填写 [acceptance.md](acceptance.md) 的图面记录。

## 论文没有画出的部分也要设计

阅读 [engineering-circuits.md](engineering-circuits.md)，按当前电路筛选工程问题；涉及偏置与参考，再读 [bias-design.md](bias-design.md)。论文图可能省略体端、共模控制、补偿、输入保护、输出缓冲、参考驱动、非重叠时钟、上电与关断。不要认为每项都必须添加，也不要默认全部已经存在。

对每项写：是否需要、实际实现或替代、理由、接口、验证办法。若用户只复现核心并明确保留理想时钟/参考，按这个范围完成，并在整机功耗和性能中说明其影响。

## 验证按机制选择

| 模块/系统 | 优先解决的问题 | 通过以后再做 |
|---|---|---|
| 偏置/参考 | 启动、真实负载下电流与电压、余量、使能与恢复 | 电源/温度/工艺敏感性、噪声、分配与失配 |
| OTA/CMFB | 差模与共模工作点、各环和耦合稳定性、输出驱动 | 目标带宽/噪声/线性度及真实大信号恢复 |
| 开关/采样/比较器 | 实际相位、复位/保持、动态参考、极性与历史依赖 | 信号相关误差、反冲、失配与系统精度 |
| RF/混频 | 实际 RF/LO/IF、匹配/负载与周期工作点 | 增益、噪声、双侧 IM3、截断敏感性及启动交叉 |
| ADC/数字链 | 实际采样时刻、码字/VALID、延迟与重建对应 | 足够长连续记录上的谱指标、校准与噪声收敛 |

细则见 [electrical.md](electrical.md)、[simulation.md](simulation.md)、[acceptance.md](acceptance.md)。不能用单模块通过替代它在真实整机中的通过。

## 失败时如何继续

先确认“正在求解哪份电路”：OA→原生网表→实际 deck→日志→数据→测量必须对应。然后依次检查真实激励、PDK/CDF、连接与端序、静态余量、动态稳定/时序、负载与数值收敛。不要上来就全局加宽、减电容或放松精度。

一次候选只检验一个可说明的假设，保留原失败和完整条件。先定比较矩阵与停止条件；出现同一机制限制时先修接口或架构，不无边界扫参。长测试、定时优化或后台持续运行超出当前任务时，按用户授权处理，不能默认永久运行。

分段数据只有在全局相位、实际状态、重叠区码字/波形一致时才能拼接；瞬态看起来平稳和短 FFT 好看都不足以证明稳定或精度。多环分析冲突时，核对断环条件和其余系统极点，并用闭环极点/Nyquist/扰动响应交叉，不把单环相位数字直接当整机结论。

## 图面和交付的语义

使用 [engineering-schematic.md](engineering-schematic.md) 保留充分工程注释，采用 [symbols.md](symbols.md) 的功能图形。图纸/cell/symbol 的标题只写当前功能和必要结构特征，参数来自当前数据库。不要写“去掉电容版”“缩小版”“改进版”“最终版”或优化过程口号；修改原因、版本和前后差异放任务变更记录。模式名如“采样/保持”可用于真实功能状态，不能与迭代过程混淆。

交付分别说明参数/连接、网表、真实行为与 GUI 的完成范围。用户需要能打开和继续维护的成果，不需要从大量日志中拼答案。完整报告的篇幅按需要决定，但条件、失败、限制和证据不能省略。
