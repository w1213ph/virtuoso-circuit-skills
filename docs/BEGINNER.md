# 第一次让 agent 搭建电路工程

可以从「我想做一个低功耗传感器放大器，输出接 ADC」开始。Agent 先从现有工程读取工艺、供电和可用模型，再确认会影响设计的输入、负载和使用条件。接下来由 agent 解释结构、选择器件、搭建并验证电路。

## 先准备什么

有本机 SMIC18 和 Cadence 时，也可以直接告诉 agent：“请搭建比较器，给我可以打开的 Maestro 测试台。在两种输入方向、标称和慢角下比较尺寸，解释哪些指标达标，并检查失配抽样是否真的改变电路响应。”两个输入方向是两项可编辑测试，报告会指向实际的原理图、历史和超限项。[从空工程开始](../examples/dynamic-comparator/README.md#打开和复跑可编辑的-ade-maestro-测试台)

想先看一次完整交付，可以把这句话发给 agent：“请运行 SKY130 电流镜案例。给我可以打开的工程和第一次运行的报告，解释为什么加长沟道能改变输出误差，也告诉我面积和速度的代价。”在有 Python、Xschem 和 ngspice 的 Linux 上，agent 只需从仓库根目录运行一条命令。报告保留初版没通过的工况，还给出候选的实测结果。[环境、命令与读图示例](../examples/sky130-current-mirror/README.md)

有论文时提供 PDF 和复现范围。准备独立的新电路时，说明用途和已知条件。以传感器放大器为例，ADC 的输入负载和采样窗口决定需要多快建立，供电与输入范围影响可用结构。Agent 会把已知条件、建议目标和仍需确认的问题列在任务记录里。遇到确实影响性能取舍的未知项，再一起确定。

真正生成 Virtuoso 电路需要可用的 Cadence、合法可访问的 PDK、仿真模型和连接工具。连接入口见 [SETUP.md](SETUP.md)。只有聊天环境时，可以先完成论文分析和设计计划；agent 应说明还缺哪些能力。

## 复制这一段开始

```text
请使用 https://github.com/w1213ph/virtuoso-circuit-skills 帮我设计电路。
我是集成电路新手，请先读取仓库 AGENTS.md 和 skills/paper-to-virtuoso/SKILL.md，
按 references/paper-reproduction.md 的流程执行。

我的用途：[用一句话描述，按论文搭建时附上论文和图号]
目标工艺/电源：[填写，或从当前工程读取]
工程与连接：[填写，或读取已有配置]
我最关心的效果：[填写；不知道时请从论文解释可选目标]

请先读取工程，把已知条件、建议指标、测量条件和未决问题写清楚，
说明哪些设计选择需要我决定。给出初始尺寸、供电和功耗预算的依据。
请检查需要补充的偏置、共模反馈、参考、启动、关断、修调、
时钟和输出负载，解释哪些需要补充、为什么需要。
在独立任务库搭建实际 PDK 电路、功能 symbol、测试台与仿真环境。
先验证关键模块，再接整机。用前仿计划记录各指标，失败时保留证据。
电路应分层清楚、对称整齐、关键通路和反馈能沿实体线读懂。
工程注释说明作用、条件、设计目标与真实结果；图纸只描述当前功能，
不使用“去掉电容版”“改进版”等迭代过程名称。
给出器件有效尺寸、阵列总量和有依据的占地估算。
最后交付能打开的工程、真实截图、结果、限制、依赖及回退方法。
```

已有图只需要整理时，改用 [AI_START.md](AI_START.md) 的整理提示；那种任务不应自动改偏置、参数或启动仿真。

没有论文、要搭功能工程时，使用[工程搭建提示](AI_START.md#从功能需求搭建或继续工程)；已有电路需要性能提升时，使用[优化提示](AI_START.md#优化已有电路的性能)。常见模型/CDF、共模、时序、测量与交付问题已归纳为[排错清单](../skills/paper-to-virtuoso/references/lessons.md)，让 agent 按任务先检查。

## agent 应当让你看见什么

有可用的 SMIC18 环境时，可以先发给 agent 一句话：“请在新目录复跑仓库的动态比较器，用我的工艺和模型扫 gm/ID，把两个尺寸的原理图和实测报告给我，并解释哪个更适合我的前级反冲预算。”配置、命令和读结果的方法见[比较器案例](../examples/dynamic-comparator/README.md#从空目录复跑)。

| 阶段 | 给新手看的结果 | 你可以检查什么 |
|---|---|---|
| 理解用途 | 功能链路、已知条件、建议目标和未决问题 | 实际要测的指标是否符合用途 |
| 选择实现 | 结构选择、器件、接口、偏置与初始尺寸的依据 | 电压、电流、负载和面积估算是否合理 |
| 验证模块 | 工作点、启动、极性、稳定性或时序结果 | 失败是否保留；条件是否明确 |
| 验证整机 | 用同一套条件比较目标、基线和候选测值 | 看到每个指标的结果、证据和未完成工况 |
| 完成交付 | 库/cell/view 入口、原理图、symbol、测试台 | 能否打开、看懂、复测和继续修改 |

例如，“增益正常”还不够。应写出频率、输入/输出及负载、增益定义与实际数值。差分增益正常也不能替代共模稳定性检查。

先看 [六管 OTA 实例](../examples/engineering-ota/README.md) 理解交付的样子。它的外部理想参考是已声明的测试条件；完整参考发生器、PVT 和版图并未由这个例子验证。新电路仍需自己的设计和验收。

流程帮助新手把任务交清楚，也约束 agent 交付证据。它不保证任意论文、工艺和指标一次成功；达不到的结果应如实保留，不能靠换测量定义变成“复现成功”。
