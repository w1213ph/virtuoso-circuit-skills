# 第一次让 agent 搭建电路工程

你可以先说想实现什么，不必先替 agent 选好每只晶体管，也不必一定有论文。这个项目让 agent 按可检查的步骤工作：解释需求或论文、补齐工程电路、使用真实工艺搭建、验证，再交付能继续维护的工程。

## 先准备什么

有论文时提供 PDF 和复现范围；没有论文时描述希望实现的功能、输入和输出，再提供使用的工艺和电源。工艺信息已经在工程里时，让 agent 自己读取。不知道指标如何填写，可以先描述用途，让 agent 解释候选目标及测量条件，再与你确定。

真正生成 Virtuoso 电路需要可用的 Cadence、合法可访问的 PDK、仿真模型和连接工具。连接入口见 [SETUP.md](SETUP.md)。只有聊天环境时，可以先完成论文分析和设计计划；agent 应说明还缺哪些能力。

## 复制这一段开始

```text
请使用 https://github.com/w1213ph/virtuoso-circuit-skills 复现附上的论文。
我是集成电路新手，请先读取仓库 AGENTS.md 和 paper-to-virtuoso/SKILL.md，
按 references/paper-reproduction.md 的流程执行。

论文与范围：[附件、图号或要实现的功能]
目标工艺/电源：[填写，或从当前工程读取]
工程与连接：[填写，或读取已有配置]
我最关心的效果：[填写；不知道时请从论文解释可选目标]

请检查论文省略的偏置、共模反馈、参考、启动、关断、修调、
时钟和输出负载，解释哪些需要补充、为什么需要。
在独立任务库搭建实际 PDK 电路、功能 symbol、测试台与仿真环境。
先验证关键模块，再接整机；失败时找原因并保留失败结果。
电路应分层清楚、对称整齐、关键通路和反馈能沿实体线读懂。
工程注释说明作用、条件、设计目标与真实结果；图纸只描述当前功能，
不使用“去掉电容版”“改进版”等迭代过程名称。
按各阶段证据推进，不以保存成功或仿真零错误代替指标通过。
最后交付能打开的工程、真实截图、结果、限制、依赖及回退方法。
```

已有图只需要整理时，改用 [AI_START.md](AI_START.md) 的整理提示；那种任务不应自动改偏置、参数或启动仿真。

没有论文、要搭功能工程时，使用[工程搭建提示](AI_START.md#从功能需求搭建或继续工程)；已有电路需要性能提升时，使用[优化提示](AI_START.md#优化已有电路的性能)。常见模型/CDF、共模、时序、测量与交付问题已归纳为[排错清单](../skills/paper-to-virtuoso/references/lessons.md)，让 agent 按任务先检查。

## agent 应当让你看见什么

| 阶段 | 给新手看的结果 | 你可以检查什么 |
|---|---|---|
| 理解论文 | 一张功能链路图；论文给了什么、缺了什么 | 实现范围是否符合你的目标 |
| 选择实现 | 实际器件、供电、接口、偏置与负载的解释 | 真实电路与理想假设是否分清 |
| 验证模块 | 工作点、启动、极性、稳定性或时序结果 | 失败是否保留；条件是否明确 |
| 验证整机 | 与论文相同定义的指标对照 | 是实测、仿真、推算还是待验证 |
| 完成交付 | 库/cell/view 入口、原理图、symbol、测试台 | 能否打开、看懂、复测和继续修改 |

例如，“增益正常”还不够。应写出频率、输入/输出及负载、增益定义与实际数值。差分增益正常也不能替代共模稳定性检查。

先看 [六管 OTA 实例](../examples/engineering-ota/README.md) 理解交付的样子。它的外部理想参考是已声明的测试条件；完整参考发生器、PVT 和版图并未由这个例子验证。新电路仍需自己的设计和验收。

流程帮助新手把任务交清楚，也约束 agent 交付证据。它不保证任意论文、工艺和指标一次成功；达不到的结果应如实保留，不能靠换测量定义变成“复现成功”。
